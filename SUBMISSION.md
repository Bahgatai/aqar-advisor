## Elevator pitch (~30 words)

Aqar Advisor helps Egyptian home buyers ask questions in their own dialect
while keeping their budget and preferences on their own device: Gemini Nano
understands the question locally, and cloud Gemini only steps in for deep
answers — or when the device can't run AI at all.

## Inspiration

I've spent 14 years in Egyptian real-estate marketing and sales. The first
thing every buyer tells an agent is their budget, family situation, and the
districts they're considering — and they say it in Egyptian Arabic, casually,
in one long sentence. That sentence is the most sensitive data in the whole
journey, and today it goes straight to a server.

When I read about Firebase AI Logic hybrid inference, the mapping was
immediate: understanding the buyer's question is a small, fast, private task
that belongs on the device. Comparing compounds and explaining price drivers
is a heavy reasoning task where cloud Gemini earns its keep. And the 80% of
buyers on phones and browsers without on-device AI should get the same
experience with zero extra code — that's exactly what the hybrid SDK
promises.

## What it does

Aqar Advisor is an Egyptian-Arabic (RTL) web app:

1. You browse sample Cairo-area listings (12 illustrative entries, clearly
   labeled as sample data).
2. You ask in plain Egyptian Arabic: "عايز شقة ٣ غرف في التجمع بحد أقصى ٥ مليون"
   ("I want a 3-bedroom in New Cairo, max 5 million").
3. **On-device (Gemini Nano via the Prompt API, through Firebase AI Logic
   `PREFER_ON_DEVICE`):** your question is understood into a structured
   search intent — budget, rooms, areas — without anything leaving the
   browser. Listings filter instantly.
4. **Cloud (Gemini via Firebase AI Logic):** a real-estate advisor answer —
   recommendation, reasoning, one practical tip — generated by cloud Gemini
   with the sample listings as context.
5. **Every answer carries a source badge** (⚡ on-device / ☁️ cloud) driven by
   the SDK's own `response.inferenceSource`, plus live latency and a running
   device-vs-cloud counter. The hybrid split is visible, not claimed.
6. A status bar shows the on-device model state and lets the user preload it
   with live download progress (`initializeDeviceModel`).

Open it in Chrome Desktop 139+ with the built-in model: intent extraction
runs fully on-device. Open it in any other browser: the same code path falls
back to the cloud automatically. That difference *is* the demo.

## How we built it

- **Firebase AI Logic Web SDK (v13)** with the **Gemini Developer API**
  provider (no-cost tier; Spark plan, no billing).
- Two `GenerativeModel` instances, both `InferenceMode.PREFER_ON_DEVICE`:
  a small structured-output model for intent extraction (JSON out), and an
  advisor model for deep Arabic answers. A third `ONLY_IN_CLOUD` instance is
  a belt-and-braces retry if the hybrid call stalls.
- **Firebase App Check** protects the Gemini API (enforced; a
  console-registered debug token ships with the demo build, as the rules
  allow).
- Sample dataset of 12 Cairo listings baked in (labeled illustrative; no
  real-market claims).
- Vanilla HTML/CSS/JS, ES modules from the official Firebase CDN, no build
  step. Hosted on GitHub Pages.
- Fully RTL, Egyptian Arabic UI with the Cairo font.

## Challenges we ran into

- **The silent hang:** with `PREFER_ON_DEVICE` and no explicit
  `onDeviceParams`, the SDK's availability probe can wait forever on an
  on-device model download that will never finish (e.g. Chrome without the
  built-in model). The request never reaches the network and never errors.
  Fix: always pass explicit `createOptions`, plus a 25s timeout that retries
  on a `ONLY_IN_CLOUD` model. Lesson: hybrid needs a fallback for the
  fallback.
- **Language probes:** declaring Arabic as an expected *output* language made
  Chrome's availability check unreliable. We keep the Arabic instruction in
  the prompt and let the badge tell the truth about where the answer ran.
- **RTL + Arabic-Indic digits** in both UI and prompts ("٥ مليون" must parse
  as 5,000,000 EGP).

## Accomplishments that we're proud of

- A real hybrid split visible in one session: intent on-device, deep answer
  in cloud, each with its badge from `response.inferenceSource` — not
  simulated.
- The fallback path is not an error state: a browser with no on-device AI
  gets the full experience, which is the whole point of hybrid.
- Domain depth: the advisor speaks Egyptian Arabic, reasons about EGP
  budgets, down payments and installment years, and never invents listings.

## What we learned

- How Firebase AI Logic's four inference modes behave in practice, and that
  `inferenceSource` makes hybrid UI honest for free.
- App Check is genuinely part of shipping client-side Gemini; debug tokens
  make hackathon demos possible without weakening enforcement.
- On-device Prompt API is single-turn: multi-turn chat has to be packed into
  single prompts.

## What's next for Aqar Advisor

- Wire the intent filter to EREX's live listing feed (Firestore) instead of
  the sample dataset.
- Remote Config for model names and feature flags (per Firebase guidance).
- Voice input (buyers talk, they don't type) via the Prompt API's multimodal
  inputs as they land.
- Android build via the same hybrid SDK for true cross-platform reach.
